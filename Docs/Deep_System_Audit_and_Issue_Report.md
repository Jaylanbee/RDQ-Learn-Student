# 🔍 RDQ 學習系統全方位深度探索與潛在問題診斷報告

**主旨：RDQ 學習系統 (Web / API / DB / EDS 協同) 5 大潛在問題與架構改善建議**

**診斷單位**：Antigravity Agent 深度架構診斷小組
**對象**：使用者、家長與 RDQ 開發團隊
**日期**：2026 年 8 月 2 日

## 📌 深度探索摘要

經過對 RDQ 生態系（包含對話機制、Web 儀表板 `dashboard.html`、FastAPI 後端 API、CQRS-lite 數據庫與 Leitner Box 演算法）的深度探索與情境模擬，我們為您梳理出 **5 大影響體驗與穩定性的潛在問題**，並提供對應的改善建議：

---

### 🚨 問題 1：【草稿防護缺失】Web 實體阻力區缺少 `localStorage` 草稿自動暫存

- **問題現象**：學生在 Web 儀表板的實體阻力解題區（Textarea / Canvas）認真打字或繪圖寫下思考過程時，若瀏覽器不小心關閉、頁面重新整理或手機跳出，輸入的內容會**完全丟失**。
- **影響**：打字到一半的思考成果消失，會嚴重打擊孩子的使用積極度。
- **💡 改善建議 (給 RDQ 團隊)**：
  - 在 `dashboard.html` 前端加入 `localStorage` 機制，輸入文字時即時 auto-save。
  - 當重新開啟網頁時，自動恢復未完成的草稿。

---

### 🚨 問題 2：【SQLite 併發鎖定】對話 API 寫入與 Web 點擊的數據庫衝突風險

- **問題現象**：當孩子在聊天視窗上傳考卷（對話發起 `POST /api/ingest`）的同時，若學生或家長也在 Web 端點擊「答對晉級 ➔」（發起 `POST /task/{item_id}/correct`），SQLite 可能會觸發 `database is locked` 錯誤而導致寫入失敗。
- **影響**：造成狀態記錄丟失或後端 500 內部伺服器錯誤。
- **💡 改善建議 (給 RDQ 團隊)**：
  - 開啟 SQLite 的 WAL 模式 (`PRAGMA journal_mode=WAL;`)。
  - 後端 FastAPI 資料庫連線加入 Exponential Backoff 交易重試機制。

---

### 🚨 問題 3：【後設認知缺失】卡關時缺少「失分原因 (loss_reason)」點選回饋

- **問題現象**：目前 Web 閃卡翻牌後，僅有粗暴的「答對晉級 ➔」與「卡關降級 ↩」兩個按鈕。當學生卡關點擊降級時，系統**未讓學生標記『為什麼卡關』**。
- **影響**：SQLite 數據庫中的 `loss_reason` 欄位（`計算錯誤` | `概念錯誤` | `看錯題目` | `圖表判讀`）無法在 Web 端獲得真實數據，影響後續精準分析。
- **💡 改善建議 (給 RDQ 團隊)**：
  - 點擊「卡關降級 ↩」時，跳出 4 個極簡標籤（計算錯誤/觀念不熟/看錯題/推理不足），點選後再提交，讓弱點診斷更精確。

---

### 🚨 問題 4：【EDS 銜接斷層】欠缺「弱點圖譜一鍵匯出與跳轉」端點

- **問題現象**：當孩子在 Leitner Box 1 滯留題目超過 50% 或大考前夕，系統雖然會提示「建議移交 EDS 決勝特訓」，但目前**缺少一鍵匯出弱點 JSON 或一鍵跳轉 EDS 介面的實體按鈕/API**。
- **影響**：學生或家長不知道如何將 RDQ 累積的弱點資料順暢帶入 EDS 下游系統。
- **💡 改善建議 (給 RDQ 團隊)**：
  - 開放 `GET /api/eds/export-weaknesses` 端點。
  - 在 Web 儀表板頂部新增「🚀 一鍵導出 EDS 考前決勝圖譜」按鈕。

---

### 🚨 問題 5：【數理公式渲染】數理化科目缺少 LaTeX / KaTeX 動態美化渲染

- **問題現象**：目前的題目與解析文字中，一元二次方程式（如 `ax^2 + bx + c = 0`）或化學式（如 `H2SO4`）皆以純文字顯示，缺乏漂亮的數學排版。
- **影響**：數學與理化科目的視覺閱讀體驗較為生硬。
- **💡 改善建議 (給 RDQ 團隊)**：
  - 在 `dashboard.html` 引入輕量級 KaTeX / MathJax 渲染庫，自動將 `$...$` 或 LaTeX 語法渲染為典藏出版級的數學公式。
