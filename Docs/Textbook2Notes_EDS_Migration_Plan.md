# 五合一教育生態系：T2N、RDQ、錯題本、複習計畫與 EDS 深度整合計畫

## 一、 願景與戰略定位：打造超級學習閉環

過去的系統中，各個模組（Textbook2Notes、RDQ、EDS）各自為政，缺乏貫穿的資料脊椎。
本次升級的核心戰略，是以統一的 **「108課綱知識矩陣 (`eds_x_code`)」** 與 **「個人能力資料庫 (`review_index.db`)」** 為雙核心，將以下五大模組串聯為一個超級生態系：

1.  **Textbook2Notes (T2N) [輸入與轉化輸出]**：不僅是知識的前處理器，更是學習教材的生成中心（精美筆記、考卷）。
2.  **RDQ-Learn [日常診斷]**：低壓力的蘇格拉底式覆盤，負責填寫學生的病歷表。
3.  **錯題本 (Error Log) [弱點庫]**：自動收錄 RDQ 與 EDS 中的錯題與迷思。
4.  **複習計畫 (Study Plan) [時程管理]**：基於 Leitner 演算法的行事曆引擎。
5.  **EDS [決策與實戰]**：考前的高強度派題與 ROI 決策引擎。最終產出 **「決勝圖譜 (Decision Graph)」**。

這五個模組的資料流將完全打通，形成 **「吸收(T2N) → 檢測(RDQ) → 沉澱(錯題本) → 排程(複習計畫) → 衝刺(EDS 決勝圖譜)」** 的超級閉環。

## 二、 開發階段與工程實作細節

### Phase 1: 知識矩陣 (Knowledge Matrix) 匯入與底層基礎建設
**目標**：建立系統唯一的知識標準 (Single Source of Truth)，讓 T2N, RDQ, EDS 說同一種語言。

*   **具體功能實作**：
    *   在專案內建立 `references/knowledge-matrix/` 目錄，存放最新的各科知識矩陣 (如 `.md`, `.csv`)。
    *   **本地端讀取工具 (Tool Call)**：開發 `matrix_parser.py` 作為 Agent 的工具函數（非網路 API）。為了節省 Token，AI 不會一次讀取龐大的矩陣，而是透過本地腳本的搜尋功能（如 `search_matrix("光合作用")`）精準提取所需的 `eds_x_code`。
*   **操作流程 (Developer/System)**：
    1.  開發者將新版知識矩陣檔案放進資料夾。
    2.  系統啟動時，會自動執行檢查腳本，確保所有矩陣的代碼格式符合 `[領域]-[學習階段]-[流水號]` 的標準。
*   **學習效益**：確保系統永遠不會偏離課綱，避免浪費學生的時間去學習或複習不會考的內容。

### Phase 2: Textbook2Notes 核心邏輯重構 (對齊課綱)
**目標**：改造 T2N 的大腦，讓它產出的筆記不再只是文字，而是「機器可讀的知識節點」。

*   **具體功能實作**：
    *   **Prompt 工程改造**：修改 T2N 的 AI 指令，強制要求它在拆解課本內容時，必須使用本地端工具呼叫 `matrix_parser` 查詢，為每一段筆記打上精準的 `eds_x_code`。
    *   **【底層 JSON，展示層 Markdown】雙軌架構**：
        1.  **系統底層 (JSON)**：T2N 的原生輸出強制為機器可讀的 JSON 檔案（如下方範例），以確保後續 RDQ 與 EDS 能精準剖析知識點，避免切句錯誤的幻覺。
        2.  **展示層 (Markdown)**：在本地端撰寫一支輕量腳本，當接收到 JSON 時，瞬間將其渲染為人類易讀的 Markdown 筆記（包含標題、粗體、清單），供學生在網頁或筆記軟體中閱讀。
        ```json
        {
          "subject": "自然",
          "topic": "光合作用",
          "nodes": [
            {
              "content": "光反應在葉綠餅進行，需要光和水...",
              "eds_x_code": "Bc-Ⅳ-3",
              "is_out_of_matrix": false
            }
          ]
        }
        ```
    *   **超綱攔截機制**：如果課本內容無法對應任何矩陣代碼，T2N 必須將其標記為 `is_out_of_matrix: true`，此部分將被設定為「補充知識」，不會進入後續的 RDQ 提問與 EDS 考試中。
*   **操作流程 (User)**：
    1.  學生拍照或複製一段課本內容貼給系統。
    2.  系統底層產出 JSON，並瞬間為學生渲染出精美的 Markdown 筆記。
*   **學習效益**：將龐雜的課本內容「降維」並「結構化」，學生能一眼看出真正的考點在哪裡。

### Phase 3: T2N 多維度輸出與 EDS 決勝圖譜
**目標**：釋放 T2N 的潛力產生實體教材，並闡明 EDS 最終的決策產出。

*   **具體功能實作 (多維度輸出)**：
    *   **精美筆記模組**：承上所述，將 JSON Nodes 自動轉換為適合人類閱讀的 Markdown，支援重點高亮 (依據 `eds_x_code` 權重)。
    *   **考前精華提要**：與 `review_index.db` 聯動，只針對該學生 `status = uncertain` 的 `eds_x_code` 產生專屬的「弱點濃縮筆記」。
    *   **自測考卷模組 (Quiz Generator)**：T2N 可以基於文本內容，直接產出小考卷 (選擇/填空) 供學生進行課後快速自測。
*   **學習效益**：個人化教材的極致展現。學生的筆記不再是千篇一律，而是「只包含我不會的重點」。

### Phase 4: 資料流串接 (T2N → RDQ)
**目標**：讓 T2N 的產出成為 RDQ 的完美子彈，徹底解決 RDQ 「超綱範圍判斷模糊」的老問題。

*   **具體功能實作**：
    *   **RDQ 啟動邏輯升級**：RDQ 優先讀取 T2N 產生的 JSON 檔，將其視為「絕對範圍」。
    *   **自動化題庫生成**：RDQ 提問不再只依賴內建 `question-bank.md`，而是將 T2N 整理出來的 `nodes` 直接轉換為提問。

### Phase 5: 錯題本與複習計畫的生態系串聯
**目標**：確保學生不會「測完就忘」，透過自動化的錯題收集與 Leitner 排程來對抗遺忘曲線。

*   **具體功能實作 (錯題本 Error Log)**：
    *   **自動收錄機制**：RDQ 測出的 `uncertain/clarified`，以及 EDS 實戰測驗中答錯的題目，都會自動 INSERT 進入 `review_index.db`。
    *   **錯題本輸出 API**：開發 `generate_error_book.py`，能將累積的錯題打包成獨立的「錯題複習卷」，供學生週末重刷。
*   **具體功能實作 (複習計畫 Study Plan)**：
    *   **Leitner 排程器升級**：目前在 `leitner.py` 中已有算好 `next_review` 日期。我們將開發一個「今日任務清單 (Daily Task)」功能。
    *   **與 T2N/EDS 聯動**：當天到期的複習計畫，可以選擇交由 T2N 生成「重點複習筆記」，或是交由 EDS 進行「抽考」。
*   **操作流程 (User)**：
    1.  每天打開系統，先查看「複習計畫」跳出的今日到期卡片。
    2.  週末印出「錯題本」進行針對性重練。

### Phase 6: T2N 深度擴充模組 (Add-ons)
**目標**：補齊 T2N 在「輸入多樣性」與「視覺化/外部生態系輸出」的最後一哩路，但以低耦合方式開發，不阻塞核心主線。

*   **6-A. 圖像處理與圖表 OCR (Vision Input)**
    *   **定位**：前處理外掛 (Pre-processor)。
    *   **實作**：串接具備 Vision 能力的 LLM (如 GPT-4o)。當學生上傳課本照片時，先交由 Vision Agent 將圖片與表格轉譯為 Markdown，再餵給 T2N 核心引擎。
*   **6-B. 心智圖生成 (Mind Map Output)**
    *   **定位**：格式轉譯器 (Format Translator)。
    *   **實作**：讀取 T2N 產出的標準 JSON nodes，透過寫腳本直接轉譯為 `Mermaid.js` 語法，前端/Markdown 閱讀器渲染出樹狀心智圖。
*   **6-C. 難度自適應轉換 (ELI5)**
    *   **定位**：Prompt 的選用參數 (Optional Parameter)。
    *   **實作**：這並非網路 API 呼叫。而是在啟動 T2N 時，系統可依學生需求傳遞一個本地變數 `--mode=eli5`。若啟用，Prompt 會指示 AI 在產出的 JSON 中額外加上一個 `analogy` (生活化比喻) 欄位。這能在不增加常態 Token 消耗的情況下，將艱澀文言文轉為國中生易懂的白話文。

### 📌 補充說明： EDS 決勝圖譜 (Decision Graph)
**第一志願公式 = 108課綱知識矩陣 (`eds_x_code`) × 個人能力資料庫 (`review_index.db`) × 決勝圖譜**

在考前衝刺階段，EDS 模組會讀取 `review_index.db` 中累積的所有 `uncertain` 與 `clarified` 弱點，並與 `eds_x_code` 的歷屆考題投資報酬率 (ROI) 進行相乘運算。
最終，系統會為學生繪製出一張 **「決勝圖譜」**。這張圖譜會將考前剩餘時間，精準分配給「最常考且學生最弱」的知識點，並由 EDS 派發相應的實戰考題。這正是整個五合一生態系的最終輸出價值。
*   **6-D. 不建議納入：直接匯出 Anki 卡牌**
    *   **理由**：我們已經在 Phase 5 建構了自己的 `review_index.db` 與 Leitner 排程。若支援匯出到外部 App (Anki)，學生的學習數據就會流失到系統外，EDS 會拿不到學生的複習狀態，導致 ROI 算法崩潰。我們應該把心力放在優化我們自己的「錯題本與複習計畫」UI 上。

## 三、 開發優先順序與依賴關係

1.  **(Blocker)** 使用者提供校正完成的「各科知識矩陣」。
2.  **(基石)** 實作 Phase 1 & 2，將矩陣放進專案，並重構 T2N 的 JSON 輸出（確保帶有 `eds_x_code`）。
3.  **(輸出)** 實作 Phase 3 的 T2N 輸出功能（精美筆記、自測考卷）。
4.  **(串聯)** 修改 RDQ (Phase 4)，讓它學會吃 T2N 的 JSON 檔並寫入錯題本。
5.  **(排程)** 開發複習計畫與錯題本的讀取介面 (Phase 5)，完成超級閉環。
6.  **(擴充)** 在閉環穩定後，逐步掛載 Phase 6 的圖像辨識、心智圖與白話文模組。
