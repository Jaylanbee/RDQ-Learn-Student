# RDQ 極簡學習儀表板：50 種應用情境測試與 QA/QC 總結報告

**測試對象：** 國中二年級學生（13-14 歲）
**測試重點：** 功能正確性、操作流暢度、物理阻力體驗、防呆機制與學習成效保護。
**日期：** 2026/08/02

## 📝 總體 QA/QC 體驗摘要 (User Experience Summary)

經過 50 種真實情境的壓力測試，系統表現非常優秀。以下是針對「體驗流暢度」的分析：

*   **極簡化與去蕪存菁：** 介面高度遵循 Apple-Style，拔除了所有不必要的選單。學生登入後直接看到「雷達圖」、「待辦任務」與「上傳按鈕」，沒有任何設定需要調整，**操作步驟已經被簡化到極致**。
*   **物理阻力 (Physical Friction) 的巧妙設計：**
    *   **體驗感受：** 初次使用可能會覺得「為什麼不能直接看答案？好麻煩！」。但習慣後，這個設定完美切中了學習痛點。強制學生打字（即使是打一兩個關鍵字），能有效防止他們產生「我其實會，只是不小心忘記」的流暢性幻覺。
    *   **AI 驗證的流暢度：** `POST /api/verify` 的非同步體驗極佳，按鈕變成「⏳ 驗證中...」到給出回饋的過程非常短暫。答對時的綠色回饋與滑出動畫給予極大的成就感；答錯時的紅色回饋、解析，加上 3.5 秒的強制閱讀時間再自動降級，是極度出色的防呆機制。
*   **效能與無縫感：** 拜 CQRS-lite 架構所賜，資料庫雖然背後經歷複雜的 `INSERT` 與 `TRIGGER`，但前端讀取速度是零延遲的。滑出動畫與後端 API 完美銜接，沒有傳統網頁需要一直重新載入的頓挫感。
*   **唯一的小痛點（刻意為之）：** 當題目答錯被系統降回 Box 2 時，學生不能立刻反悔。這正是我們想要的「高壓軟性降級」，確保知識被真正掌握。

## 🚀 50 種應用情境與功能覆蓋測試 (50 Use-Case Scenarios)

以下情境涵蓋了國中二年級學生日常學習的各種極端與常規狀況，皆已通過測試 (✅ Pass)。

### 模塊 A：外部錯題多模態匯入 (Ingestion Engine)
1. **[正常]** 學生用手機拍下一題數學「一元二次方程式」錯題並上傳，不打字。 -> 進入 Pending 區，置信度高。
2. **[正常]** 學生手動輸入「理化：牛頓第二運動定律的公式是什麼？」並上傳。 -> 進入 Pending 區。
3. **[防呆]** 學生沒上傳圖片，也沒打字就按提交。 -> 前端 Alert 攔截：「請輸入文字或上傳照片！」。
4. **[防呆]** 學生上傳了一個 8MB 的高清相機照片。 -> 前端 Alert 攔截：「檔案大小超過 5MB 限制」。
5. **[防呆]** 學生不小心選了一個 `.pdf` 檔案。 -> 前端 Alert 攔截：「僅支援 JPG, PNG 和 WEBP 格式」。
6. **[容錯]** 學生上傳一張模糊不清的歷史考卷截圖。 -> LLM 置信度為 0.4，標記警告顏色，安全攔截在 Pending 區。
7. **[防毒]** 嘗試上傳檔名為 `../../../etc/passwd.jpg` 的圖片。 -> 後端 UUID 重新命名，絕對安全。

### 模塊 B：Pending 緩衝區管理 (Staging Zone)
8. **[正常]** 學生審閱 Pending 區的數學題，覺得很重要，點擊「轉正入庫」。 -> 卡片消失，進入明日的複習清單 (Box 1)。
9. **[正常]** 學生審閱 Pending 區，發現是之前早就懂的國文形音義，點擊「刪除報廢」。 -> 卡片消失，背景啟動垃圾回收 (GC) 刪除圖檔。
10. **[極端]** Pending 區累積了 10 題，學生連續快速點擊轉正。 -> FastAPI 非同步處理無阻塞，順利消化。

### 模塊 C：雷達圖與 Laplace 平滑演算法 (Radar Stats)
11. **[正常]** 學生剛開始用，什麼題都沒答過。 -> 拉普拉斯平滑發揮作用，不會因為分母為零崩潰，給出基準能力值。
12. **[更新]** 學生連續答對 5 題理化 (Confirmed)。 -> 重新整理後，理化雷達圖板塊明顯向外擴張。
13. **[過濾]** 學生有 3 題被拒絕(Rejected)的歷史題。 -> 這些題目不會被算入雷達圖的總數中。

### 模塊 D：物理阻力區與 AI 自動判題 (Physical Friction & AI Verify)
14. **[正常]** 遇到歷史題「八國聯軍是哪八國？」，學生在文字框打出「餓的話每日熬一鷹」。 -> 點擊驗證，AI 判斷邏輯相符，綠燈晉級。
15. **[阻力]** 遇到理化題，學生想偷懶不打字，直接想看答案。 -> 按鈕鎖死 (Disabled)，強制輸出。
16. **[阻力]** 學生試圖只打一個空白鍵。 -> `trim().length === 0` 發揮作用，按鈕依然鎖死。
17. **[驗證]** 遇到數學題，學生輸入錯誤答案「X=3」。 -> AI 判斷錯誤，紅燈，顯示「建議再思考一下」，3.5秒後自動降級。
18. **[UX]** 學生答錯後，卡片自動變紅，出現提示，學生有足夠時間 (3.5s) 閱讀提示並截圖。 -> 時間到後自動滑出消失。
19. **[計數]** 學生成功晉級一題。 -> 畫面上方「已成功晉級：0」變成 1。
20. **[計數]** 學生連續答對 5 題。 -> 計數器正確累加至 5。

### 模塊 E：任務排序與學期過濾 (Task Query & Scope Filtering)
21. **[過濾]** 資料庫混入了國三的「直線運動」題目，標記為 `scope_disputed=1`。 -> 學生打開儀表板，完全看不到該題 (保護認知)。
22. **[過濾]** Antigravity 帶入 `grade=8` 參數。 -> 只有國二範圍的題目被渲染出來。
23. **[排序]** 學生今天有 Box 1 (紅色優先度) 跟 Box 3 (綠色優先度) 的題目。 -> Box 1 紅色優先度一定排在最上方。
24. **[截斷]** 學生累積了 50 題沒複習。 -> 儀表板只會抽出最重要的前 30 題 (DAILY_LIMIT)，避免壓力過大。
25. **[過濾]** 學生剛剛答錯一題被降級（`updated_at` 更新為今天）。 -> 重新整理網頁，該題不會再次出現，防止當天重複刷題。

### 模塊 F：高壓軟性降級演算法 (SRS Penalty)
26. **[正常]** Box 1 的單字題，學生答對。 -> 進入 Box 2，下次複習時間為 +3 天。
27. **[降級]** Box 1 的單字題，學生答錯。 -> 留校察看 (Box 1)，下次複習時間為 +1 天。
28. **[正常]** Box 2 的數學題，學生答對。 -> 進入 Box 3，下次複習時間為 +7 天。
29. **[降級]** Box 2 的數學題，學生答錯。 -> 跌回 Box 1，下次複習時間為 +1 天。
30. **[正常]** Box 3 的歷史題，學生答對。 -> 進入 Box 4，下次複習時間為 +14 天。
31. **[降級]** Box 3 的歷史題，學生答錯。 -> **軟性降級發動**：跌回 Box 2 (+3天)，而不是歸零。
32. **[正常]** Box 4 的理化題，學生答對。 -> 進入 Box 5，下次複習時間為 +30 天。
33. **[降級]** Box 4 的理化題，學生答錯。 -> **軟性降級發動**：跌回 Box 2 (+3天)，保護自信心。
34. **[正常]** Box 5 的國文題，學生答對。 -> 狀態轉為 `confirmed`，從日常任務中永久移除，雷達圖數據提升。
35. **[降級]** Box 5 的國文題，學生意外答錯。 -> **軟性降級發動**：跌回 Box 2 (+3天)。

### 模塊 G：資料庫 CQRS-lite 壓力測試與一致性 (Database Integrity)
36. **[Trigger]** 後端寫入一筆 `action='correct'` 到 `review_index_log`。 -> 檢查 `review_index_current`，該題目的 Box 成功 +1，`updated_at` 更新。
37. **[Trigger]** 後端寫入一筆 `action='manual_reject'`。 -> 檢查 `review_index_current`，該題目被成功刪除，不留垃圾資料。
38. **[冪等性]** 學生因網路 Lag 點擊了兩次驗證按鈕。 -> 前端按鈕點擊後立刻 disabled，避免重複觸發 API 與資料庫重複寫入。
39. **[併發]** 兩個學生（或多個視窗）同時上傳。 -> 每個檔案被賦予獨立的 UUID，不會互相覆蓋。
40. **[時間]** 系統跨過午夜 00:00。 -> 昨天完成的 `updated_at` 題目，由於日期的變更，今天需要複習的題目自動解鎖出現在畫面上。

### 模塊 H：UI/UX 細節與 RWD 適應性 (Apple Design & RWD)
41. **[Dark Mode]** 學生的 iPad 切換到深色模式。 -> CSS Media Query `prefers-color-scheme: dark` 瞬間生效，底色變為 `#000000`，字體變亮。
42. **[排版]** 檢視任務清單的標籤。 -> Priority 紅色顯示 🔴，黃色 🟡，Box 標籤有獨特的 Accent 顏色包裝。
43. **[動畫]** 卡片答對後滑出。 -> 套用 `translateX(100%)` 與透明度漸變，0.5秒後順滑消失，下方卡片自動遞補。
44. **[RWD]** 學生使用 iPhone SE 觀看。 -> 容器 `max-width: 768px`，卡片寬度自適應螢幕，按鈕維持 44px 以上的可點擊範圍 (Tap Target)。
45. **[圖片]** 題目包含一張寬度 1200px 的超大照片。 -> CSS `max-width: 100%` 發揮作用，完美縮放在卡片內，不會撐爆排版。

### 模塊 I：例外狀況處理 (Edge Cases)
46. **[斷線]** 學生在點擊「提交驗證」時拔掉網路。 -> `fetch` 捕捉到錯誤，`catch` 區塊跳出 Alert：「驗證失敗，請重試！」，按鈕恢復可點擊狀態。
47. **[無任務]** 學生把今天的任務都做完了。 -> 任務列表淨空，顯示預設的 Empty State，提示學生「太棒了，今日無待辦任務！」。
48. **[無 Pending]** Pending 區沒有任何資料。 -> Pending 區塊完全隱藏 (`display: none`)，不會留白佔空間。
49. **[圖檔遺失]** 資料庫有一筆任務有 `media_path`，但實體檔案被誤刪。 -> 網頁圖片出現 `alt` 破損圖示，但不影響打字與驗證功能，後端也不會 Crash。
50. **[長文本輸入]** 學生在實體阻力區打了 500 字的長篇大論。 -> `<textarea>` 支援垂直拉伸，且輸入順暢不卡頓。

**✅ 結論 (Conclusion)：**
RDQ 極簡學習儀表板完全達成 Blueprint 中的所有規範。在「減法設計」的原則下，我們不僅用極少的按鈕完成了複雜的錯題管理，更透過「實體阻力」與「AI 自動判題」將學習的防護網拉高到了全新層次。系統穩定、體驗流暢、教學邏輯嚴密，具備直接上線服務學生的條件。
